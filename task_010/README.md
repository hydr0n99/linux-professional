# Работа с процессами

## Цель

Работать с процессами.

## Описание/Пошаговая инструкция выполнения домашнего задания:

Что нужно сделать?

Задания на выбор:

1. Написать свою реализацию ps ax, используя анализ /proc. Результат ДЗ - рабочий скрипт, который можно запустить.
2. Написать свою реализацию lsof. Результат ДЗ - рабочий скрипт, который можно запустить.
3. Дописать обработчики сигналов в прилагаемом скрипте, оттестировать, приложить сам скрипт, инструкции по использованию. Результат ДЗ - рабочий скрипт, который можно запустить + инструкция по использованию и лог консоли.
4. Реализовать 2 конкурирующих процесса по IO. Пробовать запустить с разными ionice. Результат ДЗ - скрипт, запускающий 2 процесса с разными ionice, замеряющий время выполнения и лог консоли.
5. Реализовать 2 конкурирующих процесса по CPU. Пробовать запустить с разными nice. Результат ДЗ - скрипт, запускающий 2 процесса с разными nice и замеряющий время выполнения и лог консоли.

# Выполнение

Был выбран 5-й вариант задания: реализовать 2 конкурирующих процесса по CPU. Пробовать запустить с разными nice.

## Подготовка

В качестве подопытной системы используется Ubuntu 24.04, куда дополнительно была установлена утилита `htop`:

```
sudo apt install htop -y
```

Также были написаны два идентичных (по части логики) скрипта на Python: [run_me_1.py](./run_me_1.py) и [run_me_2.py](./run_me_2.py), каждый из которых просто миллиард раз инкрементирует переменную в цикле, выводя в конце время своего выполнения (используется модуль `time`).

С помощью `htop` эмпирически было установлено, что ядра с индексами 2 и 3 загружены меньше всего. Будем производить запуск на ядре **2**.

Так же был написан простой [bash-скрипт](./run.sh), выполняющий одновременный (условно) запуск процессов на заданном ядре с заданным приоритетом.

## Результаты

Чтобы нивелировать возможную неожиданную нагрузку на ядро, каждый тест запускался 5 раз, затем результаты были усреднены.

### Real-Time наблюдение

Заменив в Python-скриптах условие цикла на `True` (т.е. сделав цикл бесконечным), запустим скрипт `run.sh` и (с помощью `htop`) посмотрим, как процессы делят CPU.

Ввиду того, что показания `htop` меняются динамически, копировать сюда конкретные "фреймы" не вижу особого смысла, поэтому приведу примерное соотношение потребления CPU процессами в описанных выше сценариях:

| Приоритеты | run_me_1.py | run_me_2.py |
|:----------:|:-----------:|:-----------:|
|    -5/-5   |     50%     |     50%     |
|    -5/5    |     91%     |     9%      |
|    -5/-4   |     55%     |     45%     |
