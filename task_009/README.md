# Пишем скрипт

## Цель

Написать bash-скрипт, который ежечасно формирует и отправляет на email отчёт о работе веб-сервера.

## Описание/Пошаговая инструкция выполнения домашнего задания:

Написать скрипт для CRON, который раз в час формирует отчёт и отправляет его на заданную почту.

Отчёт должен содержать:

* IP-адреса с наибольшим числом запросов (с момента последнего запуска)
* Запрашиваемые URL с наибольшим числом запросов (с момента последнего запуска)
* Ошибки веб-сервера/приложения (с момента последнего запуска)
* HTTP-коды ответов с указанием их количества (с момента последнего запуска)

Скрипт должен предотвращать одновременный запуск нескольких копий, до его завершения.

В письме должен быть прописан обрабатываемый временной диапазон.

# Выполнение

## Подготовка

В качестве подопытной системы используется Ubuntu 24.04, на которой предварительно был запущен nginx-сервер. ВМ подключена к локальной сети через Bridged-соединение, чтобы удобнее обращаться к ней с других устройств в сети (таковых у меня 3, помимо самой ВМ), и чтобы можно было проверить работу скрипта.

Чтобы иметь возможность отправлять электронные письма из командной строки или скрипта, необходимо установить `mailutils`:

```
sudo apt install mailutils -y
```

Затем (т.к. почта зарегистрирована на Gmail) необходимо сгенерировать в веб-интерфейсе почты штуку под названием App Password. Этот пароль предоставляет ограниченный доступ к почтовому ящику для использования в приложениях.

Затем нужно подредактировать конфиг `/etc/postfix/main.cf`, добавив туда следующие строки:

```
relayhost = [smtp.gmail.com]:587

smtp_use_tls = yes
smtp_tls_security_level = encrypt

smtp_sasl_auth_enable = yes
smtp_sasl_password_maps = hash:/etc/postfix/sasl_passwd
smtp_sasl_security_options = noanonymous
```

А в файл `/etc/postfix/sasl_passwd` нужно добавить строку:

```
[smtp.gmail.com]:587 your@gmail.com:APP_PASSWORD
```

Где `your@gmail.com` - email, а `APP_PASSWORD` - сгенерированный в веб-интерфейсе пароль.
Затем можно (или даже нужно) ограничить права доступа к файлу, обновить конфигурацию postfix и перезагрузить сервис:

```
sudo chmod 600 /etc/postfix/sasl_passwd
sudo postmap /etc/postfix/sasl_passwd
sudo systemctl restart postfix
```

Теперь можно отправлять письма себе (или кому-то другому) прямо из терминала:

```
mail -s test_subject your@gmail.com < "test letter"
```

## Наполнение логов

В конфиг (`/etc/nginx/sites-available/default`) были добавлены несколько записей для формирование `error.log`:

```
location /api {
   proxy_pass http://127.0.0.1:9999;
}
location /slow {
   proxy_pass http://10.255.255.1;
   proxy_connect_timeout 1s;
}
location /forbidden {
   deny all;
}
```

А также был создан файл `secret.txt` в каталоге `/var/www/html/` с правами `000`. Затем nginx был перезапущен с помощью `sudo systemctl reload nginx`, после чего с разных устройств в случайном порядке выполнялось подключение по случайным (из упомянутых ранее) URL.
